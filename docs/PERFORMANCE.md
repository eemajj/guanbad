# ความเร็ว: งบและผลวัด

## งบ (จาก ROADMAP)

| ตัวชี้วัด | เป้าหมาย | วัดได้ (31 ต.ค. 2569) |
|---|---|---|
| JS ที่โหลดครั้งแรกต่อหน้า | ≤ 130 KB | 103–121 KB (หน้ารอบตี 121 KB) |
| เวลาเซิร์ฟเวอร์ตอบหน้ารอบที่กำลังตี (p95) | ≤ 300 ms | 70 ms |
| ข้อมูลต่อครั้งที่เช็คอัปเดต ถ้าไม่มีอะไรเปลี่ยน | ≤ 1 KB | 7 ไบต์ (`{"v":22}`) |
| กด "จบเกม" จนเกมใหม่ขึ้น | ≤ 1 วินาที | 126–205 ms |
| อีกเครื่องเห็นผล | (ใหม่) | ปกติ 1.3–5 วินาที, แย่สุดประมาณ 10 วินาที (ดู ADR 0005) |

เวลาตอบของหน้าอื่น (p50 / p95): หน้าแรก 28/33 ms · สถิติ 23/27 ms · การเงิน 59/72 ms · บิลในรอบ 46/56 ms

**ข้อควรรู้:** วัดในเครื่องเดียวกับฐานข้อมูล ข้อมูลตัวอย่างขนาดเล็ก ตอนใช้จริงบน Vercel + Neon:
- จะช้ากว่านี้ตามระยะทางเครือข่ายไปฐานข้อมูล
- ควรเลือก region เดียวกันทั้งสองฝั่ง เช่น Singapore
- Neon แพ็กเกจฟรีจะหลับเมื่อไม่มีคนใช้ ครั้งแรกที่ปลุกอาจใช้เวลา 0.5–1 วินาที

## ทำอะไรไปบ้าง
- **อัปเดตหน้าจอ:** เช็คเลข version แทนการโหลดใหม่ทุก 8 วินาที (ADR 0005)
- **รายชื่อทะเบียน:** โหลดเฉพาะเมื่อหัวก๊วนอยู่ในแท็บผู้เล่น
- **ผลการแข่งทั้งหมด** (ใช้ในสถิติ อันดับ และสถิติรายคน): cache ไว้ (`unstable_cache` tag `results`) ล้างเฉพาะเมื่อผลเปลี่ยน คือจบเกม แก้ผล หรือลบรอบ
- **index ใหม่:** `MatchPlayer(memberId)` และ `Charge(memberId, status)` สำหรับหน้าสมาชิกและยอดค้าง
- **ปุ่มที่ใช้บ่อย** (ยืนยันรับเงิน ขอพัก กลับมาเล่น ลงชื่อ): เปลี่ยนเป็นผลลัพธ์ทันทีที่กด ไม่ต้องรอเซิร์ฟเวอร์

## วัดซ้ำ
- JS: ดูตาราง `First Load JS` ท้าย `npm run build`
- จบเกมจนเกมใหม่ขึ้น และอีกเครื่องเห็นผล: `npm run test:e2e` บันทึกไว้ใน annotation ของ `live.spec.ts` (ดูใน HTML report)
