# คู่มือดูแลระบบ

สำหรับคนที่ดูแลเว็บหลังขึ้นใช้งานจริง

## 1. สำรองข้อมูล

ข้อมูลเงินของก๊วนอยู่ในฐานข้อมูลที่เดียว ต้องมีสำรองอย่างน้อย 2 ชั้น:

| ชั้น | ทำอะไร | ความถี่ |
|---|---|---|
| อัตโนมัติจากผู้ให้บริการ | Neon: เปิด *Point-in-time restore* (แพ็กเกจฟรีย้อนได้ 24 ชม.) · Supabase: *Daily backups* | ตลอดเวลา |
| ไฟล์สำรองของเราเอง | `scripts/backup.sh` แล้วเก็บไฟล์ไว้ที่อื่น (Google Drive) | สัปดาห์ละครั้ง และก่อนอัปเดตเวอร์ชันใหญ่ |

```bash
DATABASE_URL="<URL ฐานข้อมูลจริง>" scripts/backup.sh
```

ไฟล์จะอยู่ในโฟลเดอร์ `backups/` (ไม่ถูก commit ขึ้น git) ต้องมี `pg_dump` เวอร์ชันเดียวกับเซิร์ฟเวอร์หรือใหม่กว่า

## 2. กู้คืน (และซ้อมกู้คืน)

ระบบกู้คืนลง **ฐานข้อมูลว่างใหม่** เท่านั้น ไม่เขียนทับของเดิม

1. สร้างฐานข้อมูลใหม่ (Neon: *Branches → New branch* หรือสร้าง database ใหม่)
2. รัน:
   ```bash
   scripts/restore.sh backups/guan-YYYYMMDD-HHMMSS.dump "<URL ฐานข้อมูลใหม่>"
   ```
3. สคริปต์แสดงจำนวนสมาชิก รอบ เกม บิล และประวัติ ให้เทียบกับของเดิม
4. ถ้าจะใช้ฐานข้อมูลที่กู้คืนแทนของจริง ให้เปลี่ยน `DATABASE_URL` ใน Vercel แล้ว redeploy

**ซ้อมกู้คืนทุก 3 เดือน** ทำตามขั้น 1–3 ด้วยไฟล์สำรองล่าสุด ถ้าจำนวนตรงกันแสดงว่าไฟล์สำรองใช้ได้จริง
(ซ้อมครั้งแรก 31 ต.ค. 2569 บนฐานข้อมูลทดสอบ: จำนวนตรงกันทุกตาราง)

## 3. ดู error

- ทุก error ถูกบันทึกเป็น JSON บรรทัดเดียว มี `ref` (รหัสอ้างอิง)
- ผู้ใช้จะเห็นรหัสเดียวกันในข้อความ error เช่น "รหัสอ้างอิง a1b2c3"
- **Vercel:** Project → *Logs* → ค้นด้วยรหัสอ้างอิง
  - `scope: "action"` = error ตอนกดปุ่ม
  - `scope: "render"` = error ตอนเปิดหน้า
- อยากได้การแจ้งเตือนอัตโนมัติ: Vercel *Log Drains* ส่งต่อไป Better Stack หรือ Axiom (มีแพ็กเกจฟรี) แล้วตั้ง alert เมื่อมี `"level":"error"`

## 4. ประวัติการแก้ไข

- หัวก๊วนเปิดได้ที่ **ตั้งค่า → ประวัติการแก้ไข** หรือแท็บ **ประวัติ** ในแต่ละรอบ
- เรื่องที่บันทึก:
  - เงิน: แจ้งโอน ยืนยัน ยกเว้น แก้กลับ รายจ่าย จบรอบ/เปิดรอบใหม่
  - เปลี่ยนเลขพร้อมเพย์
  - ผลการแข่งและการแก้ผล
  - เพิ่ม/ลบคนในรอบ
  - การเปลี่ยนระดับมือและสิทธิ์หัวก๊วน
- ประวัติลบไม่ได้จากหน้าเว็บ ถ้าลบรอบ ประวัติการลบยังอยู่ พร้อมรายละเอียดของรอบที่ลบ

## 5. อัปเดตเวอร์ชัน

1. สำรองข้อมูล (ข้อ 1)
2. merge เข้า `main`: Vercel จะ build และรัน `prisma migrate deploy` ให้เอง (migration แบบเพิ่มเท่านั้น ไม่ลบข้อมูล)
3. เปิดเว็บ ลองล็อกอิน แล้วเปิดหน้ารอบล่าสุด

## 6. เรื่องที่ต้องระวัง

- **ห้ามตั้ง `ALLOW_DEV_LOGIN`** บนเว็บจริง ไม่อย่างนั้นใครก็ล็อกอินเป็นชื่ออะไรก็ได้
- **ถ้า `AUTH_SECRET` หลุด:** เปลี่ยนค่าใหม่ใน Vercel แล้ว redeploy ทุกคนจะต้องล็อกอินใหม่ แต่ข้อมูลไม่หาย
- **หัวก๊วนคนเดียวลาออก:** ตั้งคนอื่นเป็นหัวก๊วนร่วมก่อน จาก **สมาชิก → (ชื่อ) → ตั้งเป็นหัวก๊วนร่วม** ระบบไม่ยอมให้หัวก๊วนคนสุดท้ายถอดสิทธิ์ตัวเอง
