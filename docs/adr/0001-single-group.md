# 0001 · ระบบรองรับก๊วนเดียว

- สถานะ: ตัดสินแล้ว (31 ต.ค. 2569 โดยเจ้าของระบบ)

## บริบท
ถ้าจะให้ระบบเดียวรองรับหลายก๊วน ทุกตารางต้องมี `groupId` ทุก query ต้องกรองตามก๊วน และต้องมีการสมัครหรือสร้างก๊วน การเพิ่มทีหลังต้องย้ายข้อมูลทั้งหมด

## ตัดสินใจ
รองรับ **ก๊วนเดียว** ต่อการติดตั้งหนึ่งครั้ง ข้อมูลก๊วน (ชื่อ พร้อมเพย์) อยู่ในตาราง `Setting` แถวเดียว (`id = "main"`)

## ผลที่ตามมา
- schema และ query เรียบง่าย ไม่มีโอกาสข้อมูลรั่วข้ามก๊วน
- ถ้าอีกก๊วนอยากใช้ ให้ deploy อีกชุดพร้อมฐานข้อมูลของตัวเอง (ฟรีบน Vercel + Neon)
- ถ้าวันหนึ่งต้องการหลายก๊วนในระบบเดียว ต้องเพิ่มตาราง `Group` และ `groupId` ทุกตาราง พร้อม migration ย้ายข้อมูลเดิมเข้าก๊วนแรก
