# 0005 · อัปเดตหน้าจอแบบเช็คเลข version ทุก 3 วินาที

- สถานะ: ตัดสินแล้ว

## บริบท
หลายคนเปิดหน้ารอบเดียวกันพร้อมกันที่สนาม ต้องเห็นคอร์ท คิว และผลล่าสุด เดิมหน้าโหลดใหม่ทั้งหน้าทุก 8 วินาที แม้ไม่มีอะไรเปลี่ยน ทำให้เปลืองแบตและดาต้า และข้อมูลยังช้าได้ถึง 8 วินาที

ทางเลือก:
- **WebSocket / บริการ realtime (Pusher, Supabase Realtime):** เร็วที่สุด แต่ต้องมีบริการเพิ่มและมีการเชื่อมต่อค้างไว้ตลอด
- **เช็คเลข version (เลือกแบบนี้):** ไม่ต้องมีบริการเพิ่ม พอสำหรับก๊วนที่มีคนดูพร้อมกันไม่เกินประมาณ 40 คน

## ตัดสินใจ
- `Session.version` เพิ่มขึ้นทุกครั้งที่รอบเปลี่ยน
  - ใช้ **trigger ในฐานข้อมูล** (migration `session_version`) ครอบคลุม Session, Court, Participant, Match, MatchPlayer, Charge และชื่อ/ระดับของ Member
  - เป็น trigger ทำให้ไม่มี code path ไหนลืมเพิ่มเลขได้
- `GET /api/sessions/:id/version` ตอบ `{"v":42}` (7 ไบต์)
- `ui/live-refresh.tsx` เช็คทุก 3 วินาทีระหว่างรอบกำลังตี (10 วินาทีระหว่างเปิดรับชื่อ) และเฉพาะตอนที่หน้าจอเปิดอยู่ ถ้าเลขใหม่กว่าที่แสดงอยู่ จะสั่ง `router.refresh()`
- ตัวเลข "x นาที" นับเองฝั่งเครื่อง (`ui/elapsed.tsx`) ไม่ต้องโหลดหน้าใหม่

## สิ่งที่เจอระหว่างทดสอบ (Next.js 15.5)
ใน E2E ที่เปิดเบราว์เซอร์สองเครื่อง (`tests/e2e/live.spec.ts`) ข้อมูลที่ `router.refresh()` ขอไป **บางครั้งถูกยกเลิก** (`net::ERR_ABORTED`):
- ฝั่ง server ตอบปกติ ไม่มี error ใน console และไม่มี `pagehide`
- React เริ่ม render หน้าใหม่แต่ไม่แสดงผล และ refresh ครั้งต่อๆ ไปไม่ส่ง request ออกไปสักพัก

วิธีรับมือใน `LiveRefresh`:
1. **เทียบกับ version ที่แสดงบนจอจริง:** บันทึกใน `useEffect` หลัง commit ไม่บันทึกระหว่าง render ถ้า refresh ไม่สำเร็จ รอบถัดไปจะรู้ว่ายังตามไม่ทัน
2. **ถ้ายังตามไม่ทันเกิน 2 รอบติด:** สั่ง `window.location.reload()` ข้อมูลจึงถูกต้องเสมอ

ผลวัด (10 ครั้ง ก่อนลดเป็น 2 รอบ): ผ่านทุกครั้ง
- ส่วนใหญ่เห็นผลใน 1.3–4.9 วินาที
- กรณีแย่สุด 10.5 วินาที (ต้อง reload)
- ระหว่างไม่มีอะไรเปลี่ยน ไม่มีการโหลดหน้าใหม่เลยใน 7 วินาที

## ผลที่ตามมา
- ไม่มีค่าใช้จ่ายหรือบริการเพิ่ม
- เปิดหน้าทิ้งไว้ ใช้ดาต้าประมาณ 7 ไบต์ทุก 3 วินาที
- บางครั้งหน้าจอจะ reload ทั้งหน้า (เห็นกระพริบ) เมื่อ refresh แบบนุ่มนวลไม่สำเร็จ
- ถ้าอัปเกรด Next.js แล้ว refresh ไม่หลุดอีก fallback นี้จะแทบไม่ทำงาน เทสต์ `live.spec.ts` วัดเวลาไว้ให้เทียบ
- ถ้าวันหนึ่งต้องการให้เร็วกว่านี้ หรือมีคนดูพร้อมกันเยอะมาก ให้เปลี่ยนไปใช้ Server-Sent Events หรือบริการ realtime ได้ โดยใช้ `Session.version` เดิมเป็นตัวบอกว่ามีการเปลี่ยน
